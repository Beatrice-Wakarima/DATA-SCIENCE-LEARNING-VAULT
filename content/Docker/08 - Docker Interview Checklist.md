# 🎯 Docker Interview Checklist & Cheat Sheet

> Everything you need for Docker interviews and day-to-day reference. Covers concepts, commands, and real-world scenarios.

---

## Core Concepts Q&A

**Q: What is Docker?**
A: A platform that packages applications and their dependencies into lightweight, portable containers that run identically on any system.

**Q: What is the difference between an image and a container?**
A: An image is a read-only blueprint (like a class). A container is a running instance of that image (like an object). Multiple containers can run from the same image.

**Q: What is a Dockerfile?**
A: A text file with instructions for building a Docker image. Each instruction creates a layer in the image.

**Q: What is Docker Compose?**
A: A tool for defining and running multi-container applications using a YAML file. `docker compose up` starts your entire stack.

**Q: What is the difference between CMD and ENTRYPOINT?**
```dockerfile
# ENTRYPOINT — always runs, cannot be overridden easily
ENTRYPOINT ["python"]
CMD ["main.py"]           # Default argument to ENTRYPOINT
# docker run image → python main.py
# docker run image other.py → python other.py

# CMD alone — can be fully overridden
CMD ["python", "main.py"]
# docker run image → python main.py
# docker run image bash → bash (CMD completely replaced)
```

**Q: What is a Docker volume?**
A: A mechanism for persisting data generated by containers, stored outside the container filesystem so data survives container restarts and removal.

**Q: What is a Docker network?**
A: A virtual network that allows containers to communicate with each other and the outside world. Custom networks allow containers to reference each other by name.

**Q: What is layer caching?**
A: Docker reuses unchanged layers from previous builds, making subsequent builds much faster. Copy requirements before code to maximise cache hits.

**Q: What is a multi-stage build?**
A: A Dockerfile technique that uses multiple FROM statements. Build tools are in early stages; only the final minimal stage is shipped, reducing image size and attack surface.

**Q: Difference between COPY and ADD?**
A: COPY simply copies files. ADD additionally handles URLs and auto-extracts tar archives. Best practice: always use COPY unless you specifically need ADD's extra features.

**Q: What is .dockerignore?**
A: A file that specifies which files/folders to exclude from the build context. Prevents secrets, large data files, and unnecessary files from being included in images.

## Scenario Questions

**Q: A container keeps crashing. How do you debug it?**
```bash
# Check exit code and recent logs
docker ps -a
docker logs container_name
docker logs --tail 100 container_name

# Check events
docker events --filter container=my-app

# Run with shell instead of normal command
docker run -it --entrypoint bash my-image

# Inspect the container
docker inspect container_name
```

**Q: How do you make a container's data persist?**
```bash
# Named volume — managed by Docker
docker run -v my-volume:/app/data my-image

# Bind mount — host directory
docker run -v $(pwd)/data:/app/data my-image
```

**Q: How do two containers communicate?**
```bash
# Create a network, put both on it
docker network create my-net
docker run --network my-net --name db postgres
docker run --network my-net --name app my-app
# app can reach db using hostname "db"
```

**Q: How do you reduce Docker image size?**
```
1. Use slim/alpine base image
2. Multi-stage builds
3. Combine RUN commands
4. Clean package cache in same RUN layer
5. Use .dockerignore
6. Remove dev dependencies
```

**Q: How do you handle secrets in Docker?**
```bash
# Development: .env file
docker run --env-file .env my-image

# Production: Docker secrets
echo "mysecret" | docker secret create db_password -
# Access in container: /run/secrets/db_password
```

## Complete Command Cheat Sheet

### Images
```bash
docker images                       # List images
docker pull image:tag               # Download image
docker build -t name:tag .          # Build from Dockerfile
docker build --no-cache -t name .   # Build without cache
docker tag source target            # Tag an image
docker push name:tag                # Push to registry
docker rmi image                    # Remove image
docker image prune                  # Remove unused images
docker image prune -a               # Remove ALL unused
docker history image                # Show image layers
docker inspect image                # Image details
docker save image > file.tar        # Export image
docker load < file.tar              # Import image
```

### Containers
```bash
docker run image                    # Create + start
docker run -d image                 # Run detached
docker run -it image bash           # Interactive shell
docker run --rm image               # Auto-remove when done
docker run --name name image        # Named container
docker run -p 8080:80 image         # Port mapping
docker run -e KEY=val image         # Environment variable
docker run --env-file .env image    # Env file
docker run -v host:container image  # Volume mount
docker run --network net image      # Custom network

docker ps                           # Running containers
docker ps -a                        # All containers
docker start container              # Start stopped
docker stop container               # Graceful stop
docker kill container               # Force stop
docker restart container            # Restart
docker pause container              # Pause processes
docker unpause container            # Resume

docker logs container               # View logs
docker logs -f container            # Follow logs
docker logs --tail 50 container     # Last N lines
docker exec -it container bash      # Shell into container
docker exec container cmd           # Run command
docker cp host container:path       # Copy to container
docker cp container:path host       # Copy from container
docker inspect container            # Detailed info
docker stats                        # Live resource usage
docker top container                # Running processes

docker rm container                 # Remove stopped
docker rm -f container              # Force remove
docker rm $(docker ps -aq)          # Remove all stopped
```

### Volumes
```bash
docker volume create name           # Create volume
docker volume ls                    # List volumes
docker volume inspect name          # Volume details
docker volume rm name               # Remove volume
docker volume prune                 # Remove unused
```

### Networks
```bash
docker network create name          # Create network
docker network ls                   # List networks
docker network inspect name         # Network details
docker network connect net cont     # Add container
docker network disconnect net cont  # Remove container
docker network rm name              # Remove network
docker network prune                # Remove unused
```

### Docker Compose
```bash
docker compose up                   # Start all
docker compose up -d                # Start detached
docker compose up --build           # Build + start
docker compose up service           # Start specific
docker compose down                 # Stop + remove
docker compose down -v              # Also remove volumes
docker compose ps                   # Service status
docker compose logs                 # All logs
docker compose logs -f service      # Follow service logs
docker compose exec svc bash        # Shell into service
docker compose run --rm svc cmd     # One-off command
docker compose build                # Build all images
docker compose build svc            # Build specific
docker compose pull                 # Pull latest images
docker compose restart svc          # Restart service
docker compose scale svc=3          # Scale service
```

### Cleanup
```bash
docker system prune                 # Remove unused everything
docker system prune -a              # Remove ALL unused
docker system prune -a --volumes    # Include volumes
docker system df                    # Disk usage
```

## Dockerfile Cheat Sheet

```dockerfile
FROM image:tag              # Base image
WORKDIR /path               # Set working directory
COPY src dest               # Copy files (preferred)
ADD src dest                # Copy + handle URLs/tar
RUN command                 # Execute during build
ENV KEY=value               # Environment variable
ARG KEY=default             # Build-time variable
EXPOSE port                 # Document port
VOLUME ["/path"]            # Declare volume mount
USER username               # Switch user
HEALTHCHECK CMD cmd         # Health monitoring
CMD ["cmd", "arg"]          # Default command
ENTRYPOINT ["cmd"]          # Always-run command
LABEL key=value             # Metadata
```

## Docker Compose Cheat Sheet

```yaml
version: "3.8"
services:
  service-name:
    image: image:tag          # OR
    build: ./path             # Build from Dockerfile
    container_name: name
    restart: always           # no|always|on-failure|unless-stopped
    ports:
      - "host:container"
    environment:
      KEY: value
    env_file:
      - .env
    volumes:
      - host:container        # Bind mount
      - named-vol:container   # Named volume
    networks:
      - network-name
    depends_on:
      - other-service
    healthcheck:
      test: ["CMD", "cmd"]
      interval: 30s
      timeout: 10s
      retries: 3

networks:
  network-name:

volumes:
  named-vol:
```
